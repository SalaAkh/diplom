# Аннотация

Дипломный проект посвящён разработке цифровой системы самопознания, предназначенной для анализа личностных предпочтений и определения направлений развития пользователя. Система реализована в виде прогрессивного веб-приложения (PWA) с использованием технологий HTML5, CSS3 и JavaScript ES6+.

В ходе работы была разработана модель анализа личностных предпочтений по 6 измерениям: рациональность, контроль, стратегическое мышление, исследовательский потенциал, индивидуализм и поиск смысла. Модель основана на теории принятия решений и реализована через интерактивные сценарии-дилеммы.

Система включает три типа тестирования: базовый сценарный тест, расширенный тест с различными форматами вопросов и когнитивный тест. Результаты визуализируются с помощью радарных и столбчатых диаграмм, а также сопровождаются текстовыми рекомендациями по направлениям развития.

Реализованы функции сравнительного анализа с профессиональными ролями, сравнение с известными личностями, отслеживание эволюции профиля, многоязычная поддержка (казахский, русский, английский) и экспорт результатов в HTML-отчёт.

Объём пояснительной записки — ХХ страниц, рисунков — ХХ, таблиц — ХХ, источников литературы — ХХ.

# Введение

Актуальность темы исследования обусловлена растущей потребностью современного общества в инструментах самопознания и личностного развития. В условиях информационного общества, характеризующегося множественностью жизненных путей и профессиональных траекторий, способность осознанно оценивать собственные предпочтения и склонности становится ключевым фактором успешной самореализации [1].

Существующие инструменты анализа личности, такие как типология Майерс-Бриггс (MBTI) и модель Большой пятёрки (Big Five), обладают рядом ограничений. В первую очередь, они зачастую сводят многообразие личности к фиксированным категориям, не учитывая динамическую природу предпочтений [2]. Кроме того, стандартные психологические тесты основаны на прямых вопросах, что делает их подверженными влиянию социальной желательности ответов [3]. Наконец, большинство существующих онлайн-инструментов требуют передачи персональных данных на сервер, что создаёт риски нарушения конфиденциальности [4].

Данные обстоятельства обусловливают необходимость разработки нового подхода к цифровому самопознанию, основанного на анализе поведенческих выборов в контексте ситуационных дилемм, с полной локальной обработкой данных и визуальным представлением результатов в виде спектра, а не типа.

**Цель работы** — разработать цифровую систему для анализа личностных предпочтений и определения направлений развития пользователя через интерактивные сценарии выбора.

# 1 Теоретические основы разработки системы самопознания

## 1.1 Психология принятия решений и анализ предпочтений

Исследования в области психологии принятия решений составляют теоретический фундамент разрабатываемой системы. Особое значение для данной работы имеет двухсистемная модель мышления, предложенная Д. Канеманом [1]. Согласно этой модели, человеческое мышление функционирует посредством двух систем: Системы 1 (быстрое, интуитивное мышление) и Системы 2 (медленное, аналитическое мышление). Данное разделение легло в основу одного из ключевых измерений разрабатываемой системы — шкалы «Рациональность ↔ Интуиция».

А. Тверски и Д. Канеман в своих исследованиях показали, что при принятии решений люди систематически отклоняются от рациональных моделей, используя когнитивные эвристики [3]. Эти эвристики — упрощённые правила принятия решений — проявляются в ситуациях выбора и могут быть зафиксированы через анализ паттернов ответов. Именно этот принцип положен в основу метода сценарных дилемм, используемого в разрабатываемой системе.

Теория перспектив, также разработанная Канеманом и Тверски, демонстрирует, что люди по-разному оценивают потенциальные выигрыши и потери [7]. Эта асимметрия восприятия проявляется в измерении «Контроль ↔ Адаптация»: одни пользователи стремятся минимизировать неопределённость и контролировать ситуацию, другие — адаптироваться к меняющимся обстоятельствам.

Важным теоретическим основанием является концепция индивидуальных различий в принятии решений [8]. Исследования показывают, что стиль принятия решений является устойчивой характеристикой личности, которая проявляется в различных контекстах. Это подтверждает валидность подхода, основанного на анализе выборов в разнообразных ситуационных дилеммах.

Для разрабатываемой системы особое значение имеет понятие контекстуальных предпочтений [9]. Предпочтения пользователя не являются абсолютными — они зависят от контекста принятия решения. Поэтому в системе используются разнообразные сценарии, моделирующие различные жизненные ситуации: карьерные дилеммы, межличностные отношения, творческие задачи и другие.

Таким образом, психология принятия решений предоставляет научно обоснованную методологическую базу для разработки цифровой системы самопознания. Анализ поведенческих выборов в контексте дилемм позволяет выявить устойчивые паттерны мышления и предпочтений пользователя.

## 1.2 Модели анализа личности: от Big Five до современных подходов

Для разработки собственной модели анализа предпочтений необходимо рассмотреть существующие модели анализа личности, их достоинства и ограничения.

**Модель Большой пятёрки (Big Five)** является наиболее признанной в академической психологии моделью личности [2]. Она описывает личность по пяти факторам: открытость опыту, добросовестность, экстраверсия, доброжелательность и нейротизм. Достоинством модели является её эмпирическая обоснованность — она была выведена на основе факторного анализа большого массива данных. Однако модель Big Five имеет ограничения: она ориентирована на описание черт характера, а не на анализ предпочтений и стиля принятия решений.

**Типология Майерс-Бриггс (MBTI)** [10] основана на теории психологических типов К. Г. Юнга и классифицирует людей по 16 типам личности на основе четырёх дихотомий. Несмотря на широкую популярность, MBTI подвергается критике со стороны академического сообщества за недостаточную тест-ретестовую надёжность [11]. Кроме того, категоризация людей по дискретным типам не отражает непрерывного характера психологических характеристик.

**Модель DISC** [12] анализирует поведенческие стили по четырём факторам: доминирование, влияние, стабильность, добросовестность. Эта модель ближе к разрабатываемой системе в том смысле, что она ориентирована на поведенческие проявления, а не на глубинные черты характера.

**Теория самодетерминации** Э. Деси и Р. Райана [13] выделяет три базовые потребности: автономию, компетентность и связанность. Эта теория повлияла на формирование измерения «Индивидуализм ↔ Коллективизм» в разрабатываемой модели.

Анализ существующих моделей позволил выявить следующие ключевые принципы, которые были учтены при проектировании собственной модели:

а) непрерывный спектр вместо дискретных типов — результаты должны представлять позицию на шкале, а не категорию;

б) фокус на предпочтениях в принятии решений, а не на чертах характера;

в) контекстуальная оценка через ситуационные дилеммы вместо прямых вопросов;

г) множественные независимые измерения для комплексного профиля.

## 1.3 Цифровые инструменты самопознания: обзор и анализ

Рынок цифровых инструментов самопознания активно развивается. Можно выделить несколько категорий существующих решений.

**Онлайн-тесты личности** (16Personalities, Truity, PersonalityPerfect) представляют собой веб-сайты, предлагающие прохождение стандартных психологических тестов. Их достоинства — доступность и простота использования. Ограничения — ориентация на типизацию (как правило, по модели MBTI), отсутствие визуализации динамики, необходимость передачи данных на сервер [14].

**Мобильные приложения** (Reflectly, Daylio, MindDoc) ориентированы на ежедневное отслеживание состояния и настроения. Они предоставляют визуализацию трендов, но не выполняют комплексного анализа предпочтений и стиля мышления.

**Корпоративные инструменты** (Gallup StrengthsFinder, Hogan Assessment) предоставляют глубокий анализ, но являются платными и ориентированы на организационный контекст.

## 1.4 Визуализация психологических данных

Визуализация данных играет ключевую роль в системах анализа личности, поскольку позволяет пользователю наглядно увидеть и осмыслить собственный профиль предпочтений [5].

**Радарные (лепестковые) диаграммы** являются наиболее подходящим инструментом для отображения многомерных профилей [15]. Они позволяют одновременно отобразить значения по всем измерениям, создавая визуально цельный образ – «отпечаток личности». Каждая ось соответствует одному измерению, а форма полигона отражает уникальную конфигурацию предпочтений.

**Столбчатые диаграммы** дополняют радарные, предоставляя точные числовые значения для каждого измерения. Они позволяют лучше сравнивать абсолютные значения показателей.

**Цветовое кодирование** используется для интуитивного восприятия уровней: высокие значения, средние и низкие маркируются различными цветами, что ускоряет считывание информации [16].

Для реализации визуализации в веб-приложениях существует ряд библиотек. Наиболее подходящей для данного проекта является библиотека Chart.js [17], обладающая следующими преимуществами:

а) поддержка радарных, столбчатых и линейных диаграмм;

б) адаптивный дизайн (responsiveness);

в) анимации при построении и обновлении графиков;

г) открытый исходный код и активное сообщество разработчиков.

## 1.5 Прогрессивные веб-приложения как платформа

Прогрессивное веб-приложение (PWA) — это веб-приложение, которое использует современные веб-технологии для предоставления пользовательского опыта, сопоставимого с нативными мобильными приложениями [6].

Ключевые характеристики PWA, обосновывающие выбор данной технологии:

а) **Работа без подключения к сети.** Service Worker позволяет кэшировать необходимые ресурсы и обеспечивать работу приложения в автономном режиме;

б) **Кроссплатформенность.** Приложение работает на любом устройстве с современным браузером — настольных компьютерах, планшетах и смартфонах;

в) **Установка на устройство.** Файл манифеста (manifest.json) позволяет пользователю добавить приложение на главный экран устройства;

г) **Отсутствие необходимости в сервере.** Все вычисления выполняются на стороне клиента, что обеспечивает конфиденциальность данных и отсутствие зависимости от серверной инфраструктуры;

д) **Мгновенное обновление.** Обновления доставляются автоматически через Service Worker.

Для хранения данных используется API localStorage [18], которое позволяет сохранять до 5–10 МБ данных в браузере пользователя. Данные хранятся в формате JSON и включают результаты тестирования, историю прохождений и пользовательские настройки.

## 2.2 Модель анализа личностных предпочтений по 6 измерениям

### 2.2.1 Выбор и обоснование измерений

Ядром разрабатываемой системы является модель анализа личностных предпочтений, включающая 6 измерений. Каждое измерение представляет собой биполярную шкалу, на которой пользователь располагается по результатам анализа его выборов в дилеммах.

**Измерение 1: Рациональность ↔ Интуиция (rationality)**

Данное измерение оценивает предпочитаемый стиль мышления при принятии решений. Пользователи с высоким показателем рациональности склонны к систематическому анализу, логическому обоснованию и структурированному подходу. Пользователи на противоположном полюсе опираются на интуицию, чутьё и целостное восприятие ситуации. Теоретической базой служит двухсистемная модель Д. Канемана [1].

**Измерение 2: Контроль ↔ Адаптация (control)**

Измерение отражает отношение к неопределённости и предпочтение в управлении ситуацией. Высокий показатель контроля характеризует стремление к планированию, структурированию и минимизации рисков. Адаптивный полюс описывает гибкость, способность приспосабливаться к изменениям и комфорт в условиях неопределённости.

**Измерение 3: Стратегическое ↔ Тактическое мышление (strategic)**

Данное измерение оценивает временной горизонт принятия решений. Стратегически ориентированные пользователи фокусируются на долгосрочных целях и глобальной перспективе. Тактически ориентированные — на конкретных, ближайших задачах и практических результатах.

**Измерение 4: Исследовательский потенциал ↔ Исполнительность (explorer)**

Измерение отражает потребность в исследовании нового против предпочтения работы в рамках установленных процедур. Высокий показатель характеризует любознательность, стремление к экспериментам и инновациям. Низкий — предпочтение проверенных методов и стабильности.

**Измерение 5: Индивидуализм ↔ Коллективизм (individualism)**

Измерение оценивает ориентацию на индивидуальные достижения и автономию против ориентации на группу, сотрудничество и командную работу. Основано на теории самодетерминации [13] и кросс-культурных исследованиях.

**Измерение 6: Поиск смысла ↔ Утилитарность (meaning)**

Измерение отражает потребность в глубинном понимании и поиске смысла деятельности против прагматической ориентации на конкретный результат и практическую пользу.

Выбор именно этих 6 измерений обусловлен следующими факторами:

а) покрытие ключевых аспектов стиля принятия решений;

б) взаимная независимость измерений (измерения не коррелируют друг с другом);

в) возможность измерения через анализ выборов в сценариях-дилеммах;

г) практическая полезность для формирования рекомендаций.

### 2.2.2 Алгоритм нормализации оценок

Для каждого сценария определены варианты выбора, каждый из которых имеет набор весов по всем 6 измерениям. Веса принимают значения в диапазоне от -1 до 1.

Алгоритм вычисления профиля пользователя включает следующие шаги:

1) Регистрация выбора. При каждом выборе пользователя фиксируются веса выбранного варианта по всем измерениям.

2) Накопление оценок. Для каждого измерения суммируются веса всех сделанных выборов:

    sum[d] = Σ weight[d][i],         (1)

    где d — измерение, i — номер сценария.

3) Нормализация. Суммарный балл делится на количество пройденных сценариев:

    normalizedScore[d] = sum[d] / N,   (2)

    где N — количество пройденных сценариев.

4) Ограничение диапазона. Значение ограничивается интервалом [-1, 1]:

    finalScore[d] = clamp(normalizedScore[d], -1, 1),   (3)

    где clamp(x, min, max) = max(min, min(max, x)).

5) Перевод в процентное представление для визуализации:

    percentage[d] = (finalScore[d] + 1) × 50,   (4)

    где результат находится в диапазоне от 0 до 100 процентов.

### 2.2.3 Система категоризации и рекомендаций

На основе комбинации значений по 6 измерениям система определяет принадлежность пользователя к одной или нескольким категориям направлений развития:

а) **Исследование и Наука** — высокие показатели рациональности и исследовательского потенциала;

б) **Творчество и Инновации** — высокие показатели исследовательского потенциала и индивидуализма;

в) **Управление и Лидерство** — высокие показатели стратегического мышления и контроля;

г) **Социальная сфера и Помощь** — низкие показатели индивидуализма (высокий коллективизм) и высокий поиск смысла.

Для каждой категории рассчитывается процент соответствия на основе формулы:

    match[c] = Σ (weight[c][d] × finalScore[d]) / Σ |weight[c][d]|,   (5)

    где c — категория, d — измерение, weight[c][d] — вес измерения d для категории c.

Система также определяет архетип личности — обобщённый профиль, наиболее соответствующий комбинации измерений пользователя. Каждый архетип описывается набором характерных черт, сильных сторон и рекомендуемых направлений деятельности.

## 2.3 Проектирование структуры данных сценариев

Сценарии хранятся в формате JSON и загружаются при инициализации приложения. Структура каждого сценария включает следующие поля:

- **id** — уникальный идентификатор сценария (целое число);
- **title** — многоязычное название сценария (объект с ключами kk, ru, en);
- **description** — многоязычное описание ситуации;
- **options** — массив вариантов выбора.

Каждый вариант выбора содержит:

- **text** — многоязычный текст варианта;
- **weights** — объект весов по 6 измерениям.

Пример структуры сценария:

    {
      "id": 1,
      "title": { "kk": "...", "ru": "Дилемма: стабильность или риск", "en": "..." },
      "description": { "kk": "...", "ru": "Вам предлагают...", "en": "..." },
      "options": [
        {
          "text": { "ru": "Принять стабильное предложение" },
          "weights": {
            "rationality": 0.3,
            "control": 0.5,
            "strategic": -0.2,
            "explorer": -0.4,
            "individualism": 0.1,
            "meaning": -0.1
          }
        }
      ]
    }

Система поддерживает загрузку сценариев из двух источников: встроенные данные (файл scenarios-data.js) и внешний файл (scenarios.json), что обеспечивает надёжность при различных условиях работы.

## 3.2 Реализация модуля сценариев и тестирования

Модуль тестирования реализован в классе TestManager и поддерживает три типа тестов.

**Базовый сценарный тест** представляет собой последовательность из 10 сценариев-дилемм. Каждый сценарий отображается с названием, описанием ситуации и двумя или более вариантами выбора. При выборе варианта его веса регистрируются по всем 6 измерениям.

Ключевой фрагмент обработки выбора:

    handleChoice(scenarioIndex, optionIndex) {
        const scenario = this.scenarios[scenarioIndex];
        const option = scenario.options[optionIndex];
        
        Object.keys(option.weights).forEach(dimension => {
            this.scores[dimension] += option.weights[dimension];
        });
        
        this.currentScenario++;
        
        if (this.currentScenario >= this.scenarios.length) {
            this.finishTest();
        } else {
            this.showNextScenario();
        }
    }

**Расширенный тест** включает дополнительные форматы вопросов:

а) шкальные вопросы (scale) — пользователь устанавливает значение на ползунке;

б) открытые вопросы (open) — текстовый ответ в свободной форме;

в) ситуационные вопросы (situational) — многошаговые сценарии с последовательными выборами.

**Когнитивный тест** оценивает когнитивный стиль мышления через специализированные задания, включающие задачи на логику, ассоциативное мышление и анализ паттернов.

## 3.3 Реализация модуля анализа личности

Модуль анализа реализован в классе PersonalityAnalyzer и выполняет следующие функции:

а) нормализация оценок по формулам (1)–(4);

б) генерация текстового профиля с описанием сильных сторон;

в) определение категорий направлений развития;

г) определение архетипа личности;

д) формирование персонализированных рекомендаций.

Процесс определения архетипа основан на анализе комбинации значений по 6 измерениям. В системе определены несколько архетипов, каждый из которых характеризуется набором пороговых значений. Система выбирает архетип с наибольшим процентом соответствия профилю пользователя.

Дополнительные модули анализа включают:

- **Сравнительный анализ (comparative-analysis.js)** — сравнение профиля пользователя с эталонными профилями профессиональных ролей (предприниматель, исследователь, менеджер, творец и другие);

- **Сервис знаменитостей (celebrity-service.js)** — определение известных личностей с похожим профилем предпочтений;

- **Отслеживание эволюции (evolution-tracker.js)** — анализ изменений профиля при повторных прохождениях теста.

## 3.4 Реализация модуля визуализации

Модуль визуализации реализован в классе ResultsVisualizer и включает следующие типы диаграмм.

**Радарная диаграмма** отображает профиль пользователя по всем 6 измерениям одновременно. Каждая ось соответствует одному измерению, значение отложено от центра (0 процентов) к краю (100 процентов). Полигон, образованный значениями, формирует уникальный визуальный «отпечаток» профиля.

Пример создания радарной диаграммы с помощью Chart.js:

    createRadarChart(scores, dimensions) {
        const labels = Object.keys(dimensions).map(key => dimensions[key].name);
        const data = Object.keys(dimensions).map(key => {
            const val = scores[key] || 0;
            return Math.round((val + 1) * 50);
        });
        
        new Chart(ctx, {
            type: 'radar',
            data: {
                labels: labels,
                datasets: [{
                    data: data,
                    backgroundColor: 'rgba(99, 102, 241, 0.2)',
                    borderColor: 'rgba(99, 102, 241, 1)'
                }]
            }
        });
    }

**Столбчатая диаграмма** предоставляет альтернативное представление тех же данных с точными процентными значениями для каждого измерения.

**Сравнительная диаграмма** накладывает профиль пользователя на эталонный профиль выбранной роли, позволяя визуально оценить сходства и различия.

## 3.5 Реализация дополнительных модулей

**Модуль локализации (i18n.js)** обеспечивает поддержку трёх языков: казахского, русского и английского. Перевод интерфейса выполняется через файлы локализации (kk.json, ru.json, en.json), содержащие пары «ключ — перевод». Элементы DOM с атрибутом data-i18n автоматически обновляются при смене языка.

**Модуль хранения (StorageManager)** обеспечивает:

а) сохранение результатов тестирования с временной меткой;

б) сохранение прогресса незавершённого теста;

в) хранение истории всех прохождений;

г) управление пользовательскими настройками (язык, тема).

**Service Worker (sw.js)** кэширует статические ресурсы приложения (HTML, CSS, JS, изображения) и обеспечивает работу в автономном режиме. При наличии сетевого подключения проверяются обновления.

**Модуль генерации отчётов (ReportGenerator)** создаёт HTML-документ с результатами тестирования, который пользователь может скачать и сохранить локально. Отчёт включает текстовый профиль, оценки по измерениям и рекомендации.
