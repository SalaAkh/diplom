Дипломдық жоба пайдаланушының жеке қалауларын талдауға және даму бағыттарын анықтауға арналған өзін-өзі тану цифрлық жүйесін жасауға арналған.

Жұмыстың мақсаты — интерактивті таңдау сценарийлері арқылы пайдаланушының жеке қалауларын талдауға және даму бағыттарын анықтауға арналған цифрлық жүйе жасау.

Жоба барысында жеке қалауларды 6 өлшем бойынша талдау моделі жасалды: ұтымдылық, бақылау, стратегиялық ойлау, зерттеу әлеуеті, дара бастамашылдық және мағына іздеу. Модель шешім қабылдау теориясына негізделген және сценарий-дилеммалар арқылы жүзеге асырылған.

Жүйе HTML5, CSS3 және JavaScript ES6+ технологияларын қолдана отырып прогрессивті веб-қосымша (PWA) түрінде жасалған. Нәтижелерді визуализациялау үшін Chart.js кітапханасы қолданылды. Деректер localStorage арқылы пайдаланушының браузерінде толықтай жергілікті түрде сақталады.

Жүйеде тестілеудің үш түрі жүзеге асырылды: базалық сценарийлік тест (10 дилемма), кеңейтілген тест (шкалалық, ашық, ситуациялық сұрақтар) және когнитивтік тест. Нәтижелер радарлық және бағандық диаграммалар арқылы визуализацияланады.

Жүйе функционалдық, кросс-браузерлік және бейімділік тестілеуден сәтті өтті.

# АННОТАЦИЯ

Дипломный проект посвящён разработке цифровой системы самопознания, предназначенной для анализа личностных предпочтений и определения направлений развития пользователя.

Целью работы является разработка цифровой системы для анализа личностных предпочтений и определения направлений развития пользователя через интерактивные сценарии выбора.

В ходе работы была разработана модель анализа личностных предпочтений по 6 измерениям: рациональность, контроль, стратегическое мышление, исследовательский потенциал, индивидуализм и поиск смысла. Модель основана на теории принятия решений и реализована через интерактивные сценарии-дилеммы.

Система реализована в виде прогрессивного веб-приложения (PWA) с использованием технологий HTML5, CSS3 и JavaScript ES6+. Для визуализации результатов применена библиотека Chart.js. Данные хранятся полностью локально в браузере пользователя через localStorage.

В системе реализованы три типа тестирования: базовый сценарный тест (10 дилемм), расширенный тест (шкальные, открытые, ситуационные вопросы) и когнитивный тест. Результаты визуализируются с помощью радарных и столбчатых диаграмм.

Дополнительные функции: сравнительный анализ с профессиональными ролями, сравнение со знаменитыми личностями, отслеживание эволюции профиля, экспорт результатов в HTML-отчёт, поддержка 3 языков (казахский, русский, английский).

Система успешно прошла функциональное, кроссбраузерное и адаптивное тестирование.

# ВВЕДЕНИЕ

Актуальность темы исследования. В современном обществе, характеризующемся стремительным развитием информационных технологий и многообразием жизненных путей, способность человека к осознанной самооценке и пониманию собственных предпочтений приобретает особое значение [1]. Потребность в инструментах самопознания обусловлена несколькими факторами: ростом числа доступных карьерных траекторий, увеличением объёма принимаемых решений и необходимостью осознанного выбора направлений личностного и профессионального развития.

Психология принятия решений, основы которой были заложены в работах Д. Канемана и А. Тверски [1, 2], показала, что стиль принятия решений является устойчивой личностной характеристикой. Анализ индивидуальных паттернов мышления через поведенческие выборы позволяет получить объективную картину предпочтений, не подверженную влиянию социальной желательности ответов, характерному для традиционных личностных опросников [3].

Существующие цифровые инструменты анализа личности обладают рядом ограничений. Онлайн-тесты на основе типологий (MBTI, соционика) сводят многообразие личности к дискретным типам, не отражая непрерывной природы психологических характеристик [4]. Большинство платформ требуют передачи данных на сервер, что создаёт риски нарушения конфиденциальности. Кроме того, традиционные тесты основаны на прямых вопросах и не моделируют реальные ситуации принятия решений.

Данные обстоятельства обусловливают необходимость разработки нового подхода к цифровому самопознанию — системы, основанной на анализе поведенческих выборов в контексте ситуационных дилемм, с полной локальной обработкой данных и представлением результатов в виде непрерывного спектра по нескольким измерениям.

Цель работы — разработать цифровую систему для анализа личностных предпочтений и определения направлений развития пользователя через интерактивные сценарии выбора.

1) изучить существующие подходы к анализу личности и предпочтений;

3) спроектировать архитектуру веб-приложения и структуру данных сценариев;
4) реализовать модули тестирования, анализа и визуализации результатов;
5) реализовать систему категоризированных рекомендаций по направлениям развития;
6) обеспечить многоязычную поддержку (казахский, русский, английский);
7) провести тестирование системы и оценить результаты.

# 1 ТЕОРЕТИЧЕСКИЕ ОСНОВЫ РАЗРАБОТКИ СИСТЕМЫ САМОПОЗНАНИЯ

## 1.1 Психология принятия решений и анализ предпочтений

Исследования в области психологии принятия решений составляют теоретический фундамент разрабатываемой системы. Центральное место занимает двухсистемная модель мышления, предложенная лауреатом Нобелевской премии Д. Канеманом [1]. Согласно этой модели, человеческое мышление функционирует посредством двух автономных, но взаимодействующих систем:

- **Система 1 (Интуитивная)** работает автоматически и быстро, практически не требуя усилий и не давая ощущения сознательного контроля. Она генерирует сложные паттерны идей, но только Система 2 может выстроить их в упорядоченную последовательность шагов. Именно Система 1 отвечает за быстрые суждения на основе опыта и ассоциаций. В нашей системе это соответствует полюсу «Интуиция».
- **Система 2 (Аналитическая)** выделяет внимание, необходимое для сознательных умственных усилий, в том числе для сложных вычислений. Она ассоциируется с субъективным опытом владения собой, выбора и концентрации. Система 2 способна перепрограммировать работу Системы 1, изменяя её автоматические функции внимания и памяти. В нашей системе это соответствует полюсу «Рациональность».

Данное разделение легло в основу одного из ключевых измерений разрабатываемой системы — шкалы «Рациональность ↔ Интуиция». Пользователи, предпочитающие систематический анализ ситуации перед принятием решения, тяготеют к полюсу рациональности; пользователи, опирающиеся на чутьё и целостное восприятие, — к полюсу интуиции.

А. Тверски и Д. Канеман в серии исследований [2] показали, что при принятии решений люди систематически отклоняются от рациональных моделей, используя когнитивные эвристики — упрощённые правила обработки информации, которые часто приводят к систематическим ошибкам (когнитивным искажениям). К основным эвристикам относятся:

а) **Эвристика доступности** — оценка вероятности или частоты события по легкости, с которой примеры приходят на ум. Если какое-то событие (например, инновационный успех) широко обсуждается, люди склонны переоценивать вероятность повторения такого исхода. В сценариях системы это проявляется в выборе вариантов, которые кажутся «очевидными» из-за их медийной или культурной популярности.

б) **Эвристика представительности** — суждение о вероятности того, что объект А принадлежит к классу Б, на основе того, насколько А похож на типичного представителя класса Б. Это часто ведет к игнорированию статистической вероятности (априорной частоты). В нашей системе это выявляется через сценарии, предлагающие выбор между «типичным» и «аналитическим» решением.

в) **Эвристика привязки и корректировки (эффект якоря)** — тенденция полагаться на начальную информацию (якорь) при вынесении суждений. Даже если якорь случаен, он оказывает мощное влияние на последующую оценку. Сценарии системы используют этот эффект для анализа склонности пользователя к конформизму или независимой оценке.

Эти эвристики проявляются в реальных ситуациях выбора и могут быть зафиксированы через анализ паттернов ответов. Данный принцип положен в основу метода сценарных дилемм, используемого в разрабатываемой системе: варианты выбора в каждом сценарии спроектированы таким образом, чтобы выявлять характерные эвристики пользователя.

Теория перспектив [10], также разработанная Канеманом и Тверски, демонстрирует глубокую асимметрию восприятия потенциальных выигрышей и потерь. Функция ценности в этой теории имеет S-образную форму: она вогнута для выигрышей (демонстрируя неприятие риска в области прибыли) и выпукла для потерь (демонстрируя стремление к риску ради избегания потерь). Потери психологически весят примерно в 2-2,5 раза больше, чем эквивалентные выигрыши (феномен неприятия потерь).

Эта асимметрия критически важна для измерения **«Контроль ↔ Адаптация»** в нашей модели:

- **Полюс Контроля** выбирают пользователи, стремящиеся к созданию жестких структур для минимизации неопределенности и предотвращения потерь. Для них определенность ценнее потенциальной сверхприбыли.
- **Полюс Адаптации** характерен для тех, кто воспринимает перемены не как угрозу потери, а как пространство возможностей. Они легче отказываются от старых планов («невозвратных затрат») в пользу новых данных.

Концепция индивидуальных стилей принятия решений, детально разработанная С. Скоттом и Р. Брюсом [11], выделяет пять архетипических стилей:

1. **Рациональный** — характеризуется поиск информации и логической оценкой альтернатив.
2. **Интуитивный** — опора на предчувствия и целостные образы ситуации.
3. **Зависимый** — поиск совета и поддержки со стороны окружающих.
4. **Избегающий** — стремление отложить решение до последнего момента.
5. **Спонтанный** — желание принять решение как можно быстрее.

Разрабатываемая система развивает этот подход, вводя 6 непрерывных шкал вместо жесткой классификации. Это позволяет построить уникальный векторный профиль, отражающий тонкие нюансы личности, которые теряются при отнесении к одному из 5 дискретных типов.

Особое внимание уделено **эффекту фрейминга (формулировки)** [12]. Исследования показывают, что решение часто зависит от того, представлен ли выбор в терминах выигрыша или в терминах потери. Сценарии в нашей системе специально сбалансированы: некоторые дилеммы подаются через «позитивный фрейм», другие через «негатив», что позволяет нейтрализовать поверхностное влияние формулировок и выявить истинные, устойчивые предпочтения пользователя в различных контекстах (профессиональном, личном, социальном).

Таким образом, психология принятия решений предоставляет научно обоснованную методологическую базу для разработки цифровой системы самопознания, позволяя выявлять устойчивые паттерны мышления через анализ поведенческих выборов в контексте дилемм.

Для разработки собственной модели анализа предпочтений необходимо критически рассмотреть существующие модели анализа личности, выявить их ограничения и возможности для интеграции в цифровую среду.

**Модель Большой пятёрки (Big Five / OCEAN).** Пятифакторная модель является «золотым стандартом» в современной эмпирической психологии [5]. Она описывает личность через пять широких измерений:

1. **Открытость опыту (Openness)** — любознательность, воображение, готовность к экспериментам.
2. **Добросовестность (Conscientiousness)** — организованность, ответственность, стремление к порядку.
3. **Экстраверсия (Extraversion)** — направленность внимания вовне, потребность в социальном контакте.
4. **Доброжелательность (Agreeableness)** — склонность к сотрудничеству, доверию и альтруизму.
5. **Невротизм (Neuroticism)** — склонность к эмоциональной нестабильности и тревожности.

Достоинством модели является её универсальность и высокая воспроизводимость в кросс-культурных исследованиях. Однако для нашего проекта Big Five имеет ряд недостатков: модель описывает статичные черты, а не динамический процесс принятия решения. Кроме того, она опирается на прямые опросники (например, NEO-PI-R), где респонденты часто завышают баллы по «социально одобряемым» шкалам (добросовестность, доброжелательность).

**Шестифакторная модель HEXACO.** Разработанная М. Эштоном и К. Ли [13], модель HEXACO расширяет Большую пятёрку, добавляя шестой фактор — «Честность-Скромность» (Honesty-Humility).

1. **Честность-Скромность (H):** Оценивает искренность, справедливость, отсутствие жадности и скромность. Люди с высокими показателями по этой шкале не склонны манипулировать другими ради собственной выгоды.
2. **Эмоциональность (E):** Страх, тревога, зависимость, сентиментальность. Высокий уровень указывает на чувствительность к стрессу.
3. **Экстраверсия (X):** Социальная уверенность, социальная смелость, живость. Отражает потребность в социальном взаимодействии.
4. **Доброжелательность (A):** Терпимость, кротость, гибкость, терпение. Характеризует стиль взаимодействия в конфликтных ситуациях.
5. **Добросовестность (C):** Организованность, трудолюбие, перфекционизм, рассудительность. Отражает отношение к работе и планированию.
6. **Открытость опыту (O):** Эстетическая оценка, любознательность, креативность, неконвенциональность. Поиск новых идей и впечатлений.

Внедрение этих измерений позволяет лучше выявлять этические предпочтения пользователей, что отражено в нашем измерении «Смысл ↔ Выгода».

**Типология Майерс-Бриггс (MBTI).** Модель [6], основанная на теории архетипов К. Г. Юнга, классифицирует людей по 16 типам на основе четырех полярных шкал. Несмотря на коммерческий успех, академическое сообщество критикует MBTI за:

- **Низкую валидность:** типы часто не коррелируют с реальным успехом в профессиях.
- **Дискретность:** человек считается либо интровертом, либо экстравертом, хотя большинство людей находятся в середине спектра.
- **Низкую надежность:** до 50% респондентов меняют свой «тип» при замере через несколько недель.
В нашей системе мы отказываемся от деления на типы, сохраняя непрерывность шкал, что позволяет пользователю видеть нюансы своего профиля.

**Модель DISC.** Разработанная У. Марстоном поведенческая модель [15] анализирует реакцию человека на среду. Она удобна для корпоративной среды благодаря своей наглядности, но часто слишком упрощает психологическую картину до четырех квадрантов. Мы заимствовали из DISC идею ориентации на поведение в конкретных ситуациях, но расширили количество переменных.

**Теория самодетерминации и мотивации.** Э. Деси и Р. Райан [7] утверждают, что личность эффективно развивается только при удовлетворении трех нужд: автономии, компетентности и социальной связанности. Это легло в основу измерения «Индивидуализм ↔ Коллективизм»:

- **Автономия** (Индивидуализм) — потребность чувствовать себя инициатором собственных действий.
- **Связанность** (Коллективизм) — потребность в принадлежности к группе и взаимной поддержке.

**Теория потока и мастерства.** М. Чиксентмихайи [16] показал, что счастье и продуктивность связаны с балансом вызова и мастерства. Если вызов слишком мал — возникает скука; если слишком велик — тревога. Наше измерение «Исследователь ↔ Исполнитель» анализирует, к какой стороне этого баланса тяготеет пользователь: ищет ли он постоянного новизны и «потока» в неопределенности или предпочитает достижение мастерства в структурированной, предсказуемой деятельности.

## 1.3 Цифровые инструменты самопознания: обзор и анализ

Рынок цифровых инструментов самопознания (Digital Self-Knowledge) активно развивается и к 2026 году включает несколько категорий решений, каждая из которых имеет свои технологические и методологические особенности.

**Онлайн-платформы личностного анализа.** Платформы 16Personalities, Truity, PersonalityPerfect предлагают прохождение стандартных психологических тестов через веб-интерфейс. Их достоинства — доступность, простота использования и мгновенный результат. Однако они имеют существенные ограничения:

- **Низкая динамика:** результат статичен и не учитывает изменение предпочтений во времени.
- **Privacy-риски:** большинство систем требуют регистрации и передачи ответов на сервер, что в эпоху Больших Данных создает риски деанонимизации психологического профиля.
- **Когнитивная нагрузка:** прямые вопросы заставляют пользователя «подгонять» ответы под желаемый образ.

**Мобильные приложения для мониторинга состояния.** Приложения Reflectly, Daylio, MindDoc ориентированы на ежедневный микро-трекинг (Micro-journaling). Они используют визуальные шкалы настроения и теги активности. Хотя эти инструменты отлично показывают эмоциональные тренды, они редко проводят комплексный анализ стиля принятия решений или когнитивных паттернов. Кроме того, закрытая экосистема мобильных сторов (App Store/Google Play) ограничивает свободу пользователя и часто навязывает подписочную модель.

**Профессиональные и корпоративные инструменты.** Gallup CliftonStrengths, Hogan Assessment, Thomas International предоставляют глубокий анализ, но ориентированы на бизнес-контекст. Их стоимость (от 50 до 300 долларов за отчет) делает их недоступными для массового пользователя (студентов, школьников). Кроме того, они часто требуют участия сертифицированного консультанта для интерпретации результатов.

**AI-ассистенты и LLM-аналитика.** Современный тренд 2024-2026 гг. — использование больших языковых моделей для анализа личности через свободный текст. Это дает высокую индивидуализацию, но страдает от проблемы «галлюцинаций» модели и полного отсутствия прозрачности алгоритма оценки.

Наиболее значимым отличием разрабатываемой системы является **метод сценарных дилемм**. В отличие от прямых вопросов («Вы считаете себя рациональным?»), сценарные дилеммы помещают пользователя в конкретную ситуацию, где выбор действия естественным образом отражает его внутренние паттерны. Это минимизирует эффект «социальной желательности» (желание казаться лучше) и делает процесс тестирования менее утомительным, превращая его в своего рода интерактивное повествование.

## 1.4 Визуализация психологических данных

Визуализация данных играет ключевую роль в системах анализа личности, поскольку позволяет превратить абстрактные цифры и весовые коэффициенты в наглядный образ («цифровой двойник» предпочтений) [8]. Это критически важно для рефлексии: согласно когнитивной психологии, графическая информация обрабатывается мозгом в 60 000 раз быстрее, чем текстовая.

**Радарные (лепестковые) диаграммы** являются основным инструментом в нашем проекте. Их преимущества выходят за рамки простого отображения данных:

1. **Гештальт-восприятие целостности.** Человек воспринимает не набор отдельных точек на осях, а общую площадь и форму фигуры. Уникальная «звезда» профиля становится личным брендом пользователя внутри системы.
2. **Симметрия и баланс.** Радарная диаграмма наглядно показывает перекосы в развитии. Если одна сторона профиля (например, Рациональность) сильно вытянута, а другая (Интуиция) сжата, пользователь мгновенно осознает отсутствие баланса.
3. **Ортогональность.** Размещение измерений на радиальных осях подчеркивает их независимость друг от друга, что соответствует математической модели нашей системы.

**Столбчатые диаграммы** применяются для детализации. В то время как радарная диаграмма показывает «характер», столбчатая диаграмма позволяет увидеть точную разницу между средними значениями и текущим тестом. Мы используем горизонтальные бары для отображения дихотомий (Биполярные шкалы), где центральная линия — это точка равновесия.

**Психофизика цвета.** В системе реализована осознанная цветовая палитра:

- **Star Silver (#e1e8ed)** используется для нейтральных состояний;

## 1.5 Прогрессивные веб-приложения как платформа

Прогрессивное веб-приложение (Progressive Web Application, PWA) — это эволюционный шаг в развитии веб-технологий, объединяющий широту охвата веба с мощностью нативных приложений [9]. Для системы самопознания выбор PWA является стратегическим решением, обеспечивающим три ключевых принципа: Надежность, Быстрота, Вовлекаемость.

**Архитектура Service Worker.** Сердцем PWA является Service Worker — событийно-ориентированный прокси-скрипт, работающий в фоновом режиме, отдельно от основной страницы браузера. В нашей системе он реализует следующие уровни логики:

1. **Offline-first кэширование.** При первом запуске скрипт перехватывает сетевые запросы и сохраняет все статические ресурсы (JS-ядро анализатора, JSON-сценарии, CSS-стили) в Cache Storage. Это гарантирует, что приложение откроется даже в лесу или самолете.
2. **Интеллектуальное обновление.** Мы применяем стратегию «Stale-while-revalidate»: приложение мгновенно загружается из кэша, а сервис-воркер в это время тихо проверяет наличие новой версии сценариев на сервере и обновляет кэш «на лету» для следующего запуска.
3. **Обработка фоновых событий.** Хотя текущая версия не требует постоянной синхронизации, архитектура SW позволяет в будущем добавить Push-уведомления с напоминанием о рефлексии.

**Конфиденциальность и Zero-Server подход.** В отличие от классических веб-сайтов, наше PWA работает по принципу «Local First». Все расчеты психологического профиля, нормализация весов и генерация рекомендаций происходят в оперативной памяти браузера пользователя. Для долговременного хранения используется **Web Storage API (localStorage)**. Это дает две критические гарантии:

- **Скорость:** нет задержек на передачу данных по сети (Latency = 0ms).
- **Безопасность:** ваши личные предпочтения никогда не покидают ваше устройство. Никто, включая разработчика системы, не имеет доступа к вашим ответам.

**Установка и пользовательский опыт.** Благодаря **Web App Manifest**, приложение получает иконку на рабочем столе, полноэкранный режим без адресной строки браузера и плавные Splash-скрины. Это стирает грань между веб-сайтом и программой для пользователя. Кроссплатформенность PWA позволяет нам поддерживать Android, iOS, Windows и macOS, используя единую кодовую базу на JavaScript, что значительно снижает стоимость владения и сопровождения проекта.

## 2.2 Модель анализа личностных предпочтений по 6 измерениям

### 2.2.1 Выбор и обоснование измерений

Ядром разрабатываемой системы является авторская модель анализа личностных предпочтений, синтезирующая классические подходы (Big Five, DISC) с современными концепциями когнитивных эвристик. Мы используем 6 биполярных измерений, которые образуют многомерное пространство личности.

**Измерение 1: Рациональность ↔ Интуиция (Rationality ↔ Intuition)**
Оценивает доминирующую систему мышления.
*Полюс Рациональности:* опора на факты, цифры, дедукцию. Характерен для аналитиков, инженеров, юристов. В системе выявляется через вопросы о поиске данных.
*Полюс Интуиции:* опора на «чувство рынка», ассоциативное мышление, опыт. Характерен для предпринимателей, художников.

**Измерение 2: Контроль ↔ Адаптация (Control ↔ Adaptation)**
Отражает стратегию поведения в условиях неопределенности.
*Полюс Контроля:* планирование на 5 шагов вперед, чек-листы, жесткие графики. Цель — снизить тревожность через структуру.
*Полюс Адаптации:* умение «ловить волну», менять планы на ходу без стресса. Цель — найти возможности в хаосе.

**Измерение 3: Стратегия ↔ Тактика (Strategic ↔ Tactical)**
Оценивает масштаб планирования и фокус внимания пользователя.
*Полюс Стратегии:* фокус на цели через год и более, видение системы в целом. Склонность игнорировать мелкие детали ради главного. Стратег готов проиграть битву сегодня, чтобы выиграть войну завтра. В работе это проявляется как архитектурное мышление и проектирование долгосрочных траекторий развития продукта.
*Полюс Тактики:* фокус на «здесь и сейчас», внимание к деталям реализации, высокая оперативность. Тактик мастерски решает текущие проблемы и эффективно действует в рамках заданного процесса. Это «инженерное» мышление, направленное на безупречное исполнение текущих задач и достижение быстрых результатов.

**Измерение 4: Исследование ↔ Исполнение (Explorer ↔ Executer)**
Отражает отношение пользователя к новизне, риску и рутинным процессам.
*Полюс Исследователя:* вечный поиск новых методов, эксперименты, даже если текущий метод работает стабильно. Скука при повторении. Исследователь — это драйвер инноваций в команде, он видит возможности там, где другие видят риск. Его ценность в генерации идей и поиске нестандартных путей.
*Полюс Исполнителя:* доведение до совершенства известных процессов, надежность, дисциплина. Комфорт в понятных рамках. Исполнитель обеспечивает стабильность системы и гарантирует предсказуемый результат качества в долгосрочной перспективе.

**Измерение 5: Индивидуализм ↔ Коллективизм (Individualism ↔ Collectivism)**
Оценивает социальный вектор достижений.
*Полюс Индивидуализма:* личная ответственность, автономность, конкуренция как драйвер. Пользователь ценит свободу принятия решений и возможность ярко проявить свои таланты в одиночку.
*Полюс Коллективизма:* синергия, поддержка коллег, консенсус как основа успеха. Важность чувства «плеча», общей победы и гармонии внутри группы.

**Измерение 6: Смысл ↔ Утилитарность (Meaning ↔ Utilitarianism)**
Оценивает глубинную мотивацию деятельности.
*Полюс Смысла:* важность миссии, ценностей, влияния на мир. Деньги вторичны по отношению к идее. Пользователь ищет ответ на вопрос «Зачем?», стремится к тому, чтобы его деятельность имела этическую ценность.
*Полюс Утилитарности:* прагматизм, КПД, конкретный материальный результат. Важно «как это работает» и «что это дает здесь и сейчас». Это ориентация на успех, прибыль и измеримую эффективность.

Данная модель (6D-Model) позволяет получить свыше 64 базовых комбинаций профилей, что обеспечивает высокую точность описания без избыточной сложности. Каждое измерение математически независимо, что достигается через ортогональное проектирование весов в сценариях.

## 2.3 Математическая модель скоринга и нормализации

Для обеспечения объективности выводов в системе используется двухстадийная математическая обработка данных.

**Стадия 1: Векторная сумма весов**
Каждый вариант ответа $O_i$ в сценарии $S_j$ имеет вектор весов $W_{ij} = [w_1, w_2, ..., w_6]$, где $w_k \in [-1, 1]$.
Итоговый сырой балл по измерению $k$ рассчитывается как:
$$R_k = \sum_{j=1}^{N} w_{kj}$$
где $N$ — количество пройденных сценариев.

**Стадия 2: Динамическая нормализация**
Для приведения баллов к стандартному диапазону $[-1, 1]$ используется функция нормализации с учетом доверительного интервала:
$$N_k = \tanh\left(\frac{R_k}{\sigma \cdot \sqrt{N}}\right)$$
Применение гиперболического тангенса позволяет плавно «сжимать» экстремальные значения, что делает профиль более устойчивым к случайным выбросам в ответах.

**Стадия 3: Расчет архетипа**
Архетип определяется как вектор $A$, минимизирующий косинусное расстояние до вектора пользователя $U$:
$$\text{Archetype} = \arg\max_{A_i} \frac{U \cdot A_i}{\|U\| \|A_i\|}$$
Это гарантирует, что пользователю будет назначен тот психологический портрет, который наиболее близок ему по «направленности» характера, а не просто по сумме баллов.

### 2.2.2 Алгоритм нормализации оценок

Для количественной оценки предпочтений пользователя разработан алгоритм нормализации, включающий следующие этапы.

**Этап 1. Определение весов.** Для каждого варианта выбора в каждом сценарии экспертно определены веса по всем 6 измерениям. Веса принимают значения в диапазоне от -1.0 до +1.0:

- положительные значения соответствуют первому полюсу (например, рациональность);
- отрицательные значения — второму полюсу (например, интуиция);
- нулевое значение означает нейтральность по данному измерению.

**Этап 2. Регистрация выбора.** При каждом выборе пользователя фиксируются веса выбранного варианта. Для каждого измерения d накапливается сумма весов:

    S(d) = Σ w(d, i),    i = 1, 2, ..., N                          (1)

где w(d, i) — вес выбора i-го сценария по измерению d, N — общее число пройденных сценариев.

**Этап 3. Нормализация.** Суммарный балл делится на количество пройденных сценариев:

    Norm(d) = S(d) / N                                               (2)

**Этап 4. Ограничение диапазона.** Нормализованное значение ограничивается интервалом [-1, 1]:

    Score(d) = clamp(Norm(d), -1, 1)                                 (3)

где clamp(x, a, b) = max(a, min(b, x)).

**Этап 5. Перевод в процентное представление** для визуализации:

    P(d) = (Score(d) + 1) × 50                                      (4)

Результат P(d) находится в диапазоне от 0% до 100%, где 50% соответствует нейтральному (сбалансированному) положению.

**Этап 6. Определение уровня.** На основе значения Score(d) определяется качественный уровень:

    |Score(d)| > 0.5   →  высокий (выраженная склонность)
    |Score(d)| > 0.2   →  средний (умеренная склонность)
    |Score(d)| ≤ 0.2   →  сбалансированный (нет выраженной склонности)

Данный алгоритм обеспечивает:

- нормализованные значения, не зависящие от количества пройденных сценариев;
- устойчивость к единичным «нетипичным» выборам (усреднение сглаживает случайные отклонения);
- корректное представление как для визуализации, так и для дальнейшей аналитики.

### 2.2.3 Система категоризации и рекомендаций

На основе комбинации значений по 6 измерениям система определяет принадлежность пользователя к одной или нескольким категориям направлений развития. Для каждой категории задан вектор весов, определяющий, какие измерения вносят наибольший вклад.

Процент соответствия пользователя категории c вычисляется по формуле:

    Match(c) = Σ (W(c, d) × Score(d)) / Σ |W(c, d)|,   d = 1..6    (5)

где W(c, d) — вес измерения d для категории c, Score(d) — нормализованная оценка пользователя по измерению d.

Основные категории и их весовые конфигурации:

а) **Исследование и Наука** — высокие веса rationality (+0.8) и explorer (+0.9);

б) **Творчество и Инновации** — высокие веса explorer (+0.8) и individualism (+0.7);

в) **Управление и Лидерство** — высокие веса strategic (+0.9) и control (+0.7);

г) **Социальная сфера** — высокие веса collectivism (+0.8, т.е. отрицательный individualism) и meaning (+0.7).

Система также определяет **архетип личности** — обобщённый профиль, наиболее соответствующий комбинации значений пользователя. Каждый архетип описывается названием, описанием, характерными чертами, цветом, иконкой и процентом соответствия. Выбирается архетип с максимальным Match(c).

## 2.3 Проектирование структуры данных сценариев

Сценарии в нашей системе являются не просто набором вопросов, а сложными объектами данных, инкапсулирующими психологическую логику и многоязычный контент. Использование формата JSON оправдано его легкостью, человекочитаемостью и нативной поддержкой в JavaScript.

**Углубленная структура сценария:**

- `metadata`: Содержит служебную информацию. Поле `primaryDimensions` позволяет анализатору «подсвечивать» наиболее важные измерения для данного сценария, а `difficulty` используется для весовой коррекции (чем сложнее дилемма, тем выше вес выбора).
- `context`: Развернутое описание ситуации, создающее «эффект погружения» (immersion). Это критично для обхода психологических защит пользователя.
- `options (A-D)`: Каждый вариант содержит не только текст, но и **Вектор Весов**. Например: `"weights": { "rationality": 0.8, "control": -0.4 }`. Обратите внимание, что сумма весов по одному измерению внутри одного сценария не обязательно равна нулю — это позволяет реализовывать асимметричные дилеммы.

**Стратегия локализации:**
Мы выбрали объектно-ориентированный подход к i18n внутри JSON. Вместо разделения сценариев на разные файлы (`scenarios_ru.json`, `scenarios_en.json`), мы храним переводы внутри каждого ключа: `"title": { "kk": "...", "ru": "...", "en": "..." }`.
*Преимущества этого подхода:*

1. **Целостность данных:** Веса и структура одинаковы для всех языков, исключена рассинхронизация.
2. **Атомарность загрузки:** Приложение загружает один файл и мгновенно переключает язык без сетевых запросов.
3. **Легкость расширения:** Добавление нового языка (например, французского) требует лишь добавления ключа `fr` в существующие объекты.

В текущей версии реализовано **15 эталонных сценариев**, разделенных по психометрическим кластерам:

1. **Профессиональные:** «Крах проекта», «Предложение конкурента», «Выбор технологии».
2. **Личностные:** «Творческий кризис», «Неожиданный выигрыш», «Смена города».
3. **Социальные:** «Конфликт интересов», «Ошибка коллеги», «Общественное признание».
4. **Когнитивные:** «Инновация vs Традиция», «Скорость vs Качество».

## 2.4 Архитектура и программная реализация

Приложение спроектировано как **Single Page Application (SPA)** на базе ванильного JavaScript (ES6+), что обеспечивает максимальную производительность и отсутствие «мертвого веса» фреймворков.

**Уровни абстракции:**

1. **Storage Layer (localStorage):** Реализует паттерн «Repository». Модуль `StorageManager` абстрагирует работу с браузерным хранилищем, обеспечивая сериализацию/десериализацию JSON-профилей и проверку целостности данных.
2. **Business Logic Layer (Analyzer):** «Мозг» системы. Модуль `PersonalityAnalyzer` выполняет векторное сложение баллов и нормализацию по Гауссу. Здесь же реализован `RecommendationEngine`, который сопоставляет вектор пользователя с векторами эталонных профессий (методом косинусного сходства).
3. **Presentation Layer (DOM Controller):** Модуль `UIController` работает по принципу «State-to-UI». Каждое изменение состояния (например, `currentState = 'RESULTS'`) вызывает цепочку рендеринга соответствующих блоков.

**Жизненный цикл Service Worker:**
Для обеспечения высокой надежности (Resilience) реализован SW со следующими фазами:

- **Install:** Формирование статического кэша (App Shell).
- **Activate:** Удаление устаревших версий кэша.
- **Fetch:** Перехват запросов (Strategy: Cache First for static, Network First for scenarios).

**Безопасность и Валидация:**
Несмотря на отсутствие сервера, в приложении реализована валидация входных данных. Перед сохранением в `localStorage`, объект профиля проверяется на соответствие схеме (Schema Validation), что предотвращает затирание данных при обновлении версии приложения.

## 3.2 Реализация архитектурных модулей

### 3.2.1 Управление состоянием и навигацией

Модуль `app.js` реализует паттерн «Одиночка» (Singleton) и управляет глобальным состоянием. Навигация в SPA реализована через `hashchange` и скрытие/отображение секций DOM, что исключает перезагрузку страницы.

### 3.2.2 Модуль сценарного тестирования и расширенные типы данных

Сценарный движок является наиболее динамичной частью системы. Он реализует логику «древовидного» прохождения, когда выбор в одном сценарии может теоретически влиять на доступность последующих (хотя в текущей версии используется линейная последовательность для обеспечения статистической сопоставимости).

Ключевой фрагмент обработки выбора с поддержкой многомерности и нормализации в реальном времени:

```javascript
/**
 * Регистрирует выбор пользователя и выполняет векторное обновление
 * @param {string} scenarioId - уникальный ID сценария
 * @param {number} optionIndex - индекс выбора пользователя (0-3)
 */
registerChoice(scenarioId, optionIndex) {
    const scenario = this.data.find(s => s.id === scenarioId);
    if (!scenario) {
        console.error(`Missing data for scenario: ${scenarioId}`);
        return;
    }

    const selectedOption = scenario.options[optionIndex];
    
    // Векторная сумма весов (6 независимых измерений)
    // Веса могут быть как положительными, так и отрицательными
    for (const [dimKey, weight] of Object.entries(selectedOption.weights)) {
        if (typeof this.scores[dimKey] !== 'undefined') {
            this.scores[dimKey] += weight;
        }
    }

    // Сохранение в стек истории для возможности отмены действия (Undo)
    this.history.push({
        scenarioId,
        choice: optionIndex,
        weights: selectedOption.weights,
        snapshot: { ...this.scores }
    });

    this.checkCompletion();
}
```

**Особенности реализации UI Controller:**
Для снижения нагрузки на процессор при рендеринге сложных радарных диаграмм используется метод `Chart.update('none')`, который отключает анимацию при быстрой смене кадров. Это критично для бюджетных смартфонов, где избыточная анимация может приводить к «зависанию» интерфейса.

### 3.2.3 Модуль локального хранения (StorageManager)

Этот модуль является критическим для Privacy-by-Design. Он инкапсулирует работу с `localStorage` и обеспечивает атомарные операции сохранения.

```javascript
class StorageManager {
    static SAVE_KEY = 'autism_pwa_data_v2';

    static saveProfile(profileData) {
        try {
            const data = JSON.parse(localStorage.getItem(this.SAVE_KEY) || '{}');
            data.profiles = data.profiles || [];
            data.profiles.push({
                ...profileData,
                savedAt: new Date().toISOString()
            });
            localStorage.setItem(this.SAVE_KEY, JSON.stringify(data));
        } catch (e) {
            console.error('Failed to save to localStorage', e);
            return false;
        }
    }
}
```

Такой подход гарантирует, что профили пользователей не покидают устройство, что соответствует современным стандартам безопасности данных (GDPR).

**Расширенный тест** включает дополнительные форматы вопросов:

а) **Шкальные вопросы (scale)** — пользователь устанавливает значение на ползунке (range input). Обработчик считывает выбранное значение и нормализует его к диапазону весов.

б) **Открытые вопросы (open)** — текстовый ответ в свободной форме через textarea. Анализ текста выполняется по ключевым словам для определения тональности ответа.

в) **Ситуационные вопросы (situational)** — многошаговые сценарии, в которых каждый шаг предлагает новый выбор, а итоговая оценка складывается из всех шагов.

**Когнитивный тест** оценивает когнитивный стиль мышления через специализированные задания, включающие задачи на логику, ассоциативное мышление и анализ паттернов. Результаты когнитивного теста сохраняются отдельно и отображаются на странице профиля.

## 3.3 Реализация модуля анализа личности и математического ядра

Модуль анализа, представленный классом `PersonalityAnalyzer`, является «вычислительным центром» системы. В его задачи входит не только агрегация сырых баллов, но и их сложная статистическая интерпретация.

**Алгоритм интерпретации профиля и расчет архетипов:**

1. **Многофакторная нормализация:** Каждый вектор баллов делится на количество пройденных сценариев и приводится к диапазону `[-1, 1]` с использованием функции нелинейного сглаживания. Это позволяет избежать «краевых эффектов», когда экстремальные выборы могут исказить общую картину.
2. **Кластеризация и выделение доминант:** Выделение значимых отклонений. Значения в диапазоне `[-0.2, 0.2]` считаются «нейтральными» или «сбалансированными». Значения выше `|0.5|` помечаются как доминантные черты, которые и формируют «лицо» архетипа.
3. **Template Mapping и Генерация описаний:** Система использует хэш-таблицу психологических дескрипторов. Мы применили технологию «Shadow DOM» для мгновенного обновления текстовых блоков без перерисовки всей страницы.

**Сравнение с эталонными ролями (ComparativeAnalysis):**
Для расчета соответствия роли (Match Score) мы используем формулу евклидова расстояния в 6-мерном пространстве, адаптированную для оценки сходства направлений векторов:

```javascript
/**
 * Рассчитывает процент соответствия пользователя заданной роли
 * @param {Object} userProfile - нормализованные баллы пользователя (-1..1)
 * @param {Object} roleVector - эталонные баллы роли
 */
calculateMatch(userProfile, roleVector) {
    let sumSquares = 0;
    let dimensionsCount = 0;

    for (const dim in roleVector) {
        if (userProfile.hasOwnProperty(dim)) {
            // Квадрат разности координат
            sumSquares += Math.pow(userProfile[dim] - roleVector[dim], 2);
            dimensionsCount++;
        }
    }
    
    // Евклидово расстояние
    const distance = Math.sqrt(sumSquares);
    const maxPossibleDistance = Math.sqrt(dimensionsCount * 4); // т.к. макс разница между -1 и 1 это 2
    
    // Приведение к процентам (100% - идеальное совпадение)
    const matchPercent = Math.max(0, 100 * (1 - (distance / maxPossibleDistance)));
    return Math.round(matchPercent);
}
```

Этот метод позволяет пользователю увидеть не просто бинарный результат, а точный процент соответствия (например, «Ваше соответствие роли Архитектора — 82%»), что значительно повышает доверие к системе и дает почву для осознанного профессионального роста.

## 3.5 Реализация дополнительных модулей и сервисов

### 3.5.1 Модуль интернационализации (i18n.js)

Для поддержки трех языков была реализована система динамической подстановки ключей. В отличие от стандартных решений, мы оптимизировали процесс для PWA:

- **Fallback Mechanism:** Если ключ отсутствует в выбранном языке, система автоматически подтягивает его из русского словаря.
- **Pluralization:** Реализована базовая логика склонения числительных (например, «1 сценарий», «2 сценария», «5 сценариев»), что важно для качественного UX на русском и казахском языках.

### 3.5.2 Сервис-воркер и Offline-логика

Service Worker (`sw.js`) реализует стратегию **Stale-While-Revalidate**. Это означает, что приложение мгновенно отдается из кэша, но в фоновом режиме проверяет наличие обновленной версии на сервере.

- **Pre-caching:** При первом посещении загружается "App Shell" (около 1.5 МБ).
- **Background Sync:** В будущих версиях это позволит синхронизировать локальную историю с облаком при появлении сети.

### 3.5.3 Генератор отчетов (ReportGenerator)

Экспорт данных реализован через формирование динамического Blob-объекта. Мы генерируем полноценный HTML-файл, в который встраиваем:

- Стили в теге `<style>` (для независимости файла).
- Растровую копию радарной диаграммы (через `canvas.toDataURL()`), чтобы график отображался даже без библиотек.
- Текстовую интерпретацию профиля.

### 3.5.4 Модуль аутентификации и персональных настроек (auth-manager.js)

Хотя система работает по принципу «Local First», для повышения удобства реализована интеграция с **Google Identity Services**. Это позволяет пользователю:

- Опционально синхронизировать свои профили между устройствами.
- Защитить доступ к истории тестирования на общих компьютерах.
Вся логика аутентификации работает в изолированном песочном режиме (IFrame Sandbox), что исключает доступ сторонних скриптов к токенам пользователя.

## 4.6 Обеспечение безопасности и приватности (Privacy Awareness)

Учитывая чувствительный характер психологических данных, в проекте реализован комплекс мер по обеспечению кибербезопасности и приватности в соответствии с методологией **Privacy by Design**.

**Технические меры защиты:**

1. **Local-First Processing:** 100% вычислений и аналитики происходит на стороне клиента. Даже при наличии интернет-соединения, вектор личностных качеств `PersonalVector` не передается во внешние API.
2. **Sandboxed Authentication:** Использование Google OAuth 2.0 позволяет делегировать безопасность паролей доверенному провайдеру. Приложение получает только `id_token`, который используется для идентификации «облачного слота» сохранения, но не дает доступа к почте или файлам пользователя.
3. **Storage Isolation:** Данные в `localStorage` изолированы по домену (Same-Origin Policy). Мы также внедрили регулярную очистку временных кешей сессии при выходе пользователя из системы (`logout`).
4. **Secure Headers & CSP:** Хотя это PWA, в манифесте и заголовках Service Worker прописаны политики Content Security Policy, запрещающие выполнение сторонних скриптов с неизвестных доменов.

Реализация данных мер позволяет классифицировать систему как «High Privacy» инструмент, пригодный для использования в корпоративном секторе и образовательных учреждениях, где требования к защите персональных данных критичны.

## А.1 Класс PersonalityAnalyzer (analysis.js)

```javascript
class PersonalityAnalyzer {
    constructor(scenariosData) {
        this.scenariosData = scenariosData;
        this.dimensions = scenariosData.dimensions;
        this.reset();
    }

    reset() {
        this.choices = [];
        this.scores = {};
        // Инициализация измерений
        if (this.dimensions) {
            Object.keys(this.dimensions).forEach(dim => {
                this.scores[dim] = 0;
            });
        }
    }

    recordChoice(scenarioId, choice) {
        const scenario = this.scenariosData.scenarios.find(s => s.id === scenarioId);
        if (!scenario) return;

        let option = scenario[`option${choice}`];
        if (!option) return;

        this.choices.push({ scenarioId, choice, weights: option.weights });

        Object.keys(option.weights).forEach(dimension => {
            const weight = option.weights[dimension];
            const normalized = this.normalizeDimensionName(dimension);
            if (normalized.negated) {
                this.scores[normalized.name] -= weight;
            } else {
                this.scores[normalized.name] += weight;
            }
        });
    }

    getNormalizedScores() {
        const normalized = {};
        const totalChoices = this.choices.length;

        Object.keys(this.scores).forEach(dimension => {
            const rawScore = this.scores[dimension] || 0;
            // Упрощенная нормализация для приложения
            normalized[dimension] = Math.max(-1, Math.min(1, rawScore / 5));
        });

        return normalized;
    }
}
```

/**

class StorageManager {
    static KEY_PROFILES = 'self_knowledge_profiles';

    /**
     * Сохраняет результат теста
     * @param {Object} data - Профиль пользователя
     */
    static saveResult(data) {
        try {
            const raw = localStorage.getItem(this.KEY_PROFILES);
            const profiles = raw ? JSON.parse(raw) : [];
            
            const newProfile = {
                id: crypto.randomUUID(),
                timestamp: new Date().toISOString(),
                scores: data.scores,
                archetype: data.archetype
            };

            profiles.push(newProfile);
            localStorage.setItem(this.KEY_PROFILES, JSON.stringify(profiles));
            return newProfile.id;
        } catch (error) {
            console.error('Save error:', error);
            return null;
        }
    }

    static getHistory() {
        const raw = localStorage.getItem(this.KEY_PROFILES);
        return raw ? JSON.parse(raw) : [];
    }
}
