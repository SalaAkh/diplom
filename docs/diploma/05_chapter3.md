# 3 РЕАЛИЗАЦИЯ СИСТЕМЫ САМОПОЗНАНИЯ

## 3.1 Выбор технологий и обоснование

Для реализации системы были выбраны следующие технологии.

**HTML5** — язык разметки, обеспечивающий семантическую структуру документа. Использованы семантические теги (header, nav, main, section, article, footer) для улучшения доступности и структурированности [24]. Применён атрибут data-i18n для маркировки переводимых элементов.

**CSS3** — язык стилей. Использованы: CSS-переменные (custom properties) для реализации тёмной и светлой тем через единый набор токенов; Flexbox и CSS Grid для адаптивной вёрстки; CSS-анимации (@keyframes) для плавных переходов между экранами; медиа-запросы (@media) для адаптации под различные размеры экранов.

**JavaScript ES6+** — основной язык программирования. Применены следующие возможности стандарта: классы (class) для объектно-ориентированной организации кода; стрелочные функции для краткости; деструктуризация объектов; шаблонные строки (template literals) для генерации HTML; промисы и async/await для асинхронных операций; модуль localStorage для хранения данных [22].

**Chart.js v4** — библиотека для построения интерактивных графиков [20]. Выбрана за поддержку радарных, столбчатых и линейных диаграмм, адаптивный дизайн (responsive), встроенные анимации и открытый исходный код.

**Обоснование отказа от фреймворков (React, Vue, Angular):**

а) проект не требует сложного управления состоянием компонентов — состояние приложения линейное и управляется конечным автоматом;

б) отсутствие серверной части делает фреймворки с их экосистемами сборки избыточными;

в) нативный JavaScript обеспечивает меньший размер приложения (без зависимостей) и более высокую производительность;

г) прямая работа с DOM проще для поддержки и отладки в контексте данного проекта;

д) отсутствие необходимости в сборщиках модулей упрощает развёртывание — достаточно разместить файлы на любом веб-сервере или открыть локально.

## 3.2 Реализация модуля сценариев и тестирования

Модуль тестирования управляется классами TestManager (логика прохождения) и UIController (отображение). Система поддерживает три типа тестов.

**Базовый сценарный тест** — последовательность из 10 сценариев-дилемм. Каждый сценарий отображается с многоязычным названием, описанием ситуации и контекстом, а также четырьмя вариантами выбора. При выборе варианта его веса регистрируются по всем 6 измерениям.

Ключевой фрагмент обработки выбора:

```javascript
handleChoice(scenarioIndex, optionIndex) {
    const scenario = this.scenarios[scenarioIndex];
    const option = scenario.options[optionIndex];

    // Регистрация весов по всем измерениям
    Object.keys(option.weights).forEach(dimension => {
        this.scores[dimension] =
            (this.scores[dimension] || 0) + option.weights[dimension];
    });

    this.currentScenario++;

    if (this.currentScenario >= this.scenarios.length) {
        this.finishTest();
    } else {
        this.showNextScenario();
    }
}
```

Данный фрагмент демонстрирует принцип накопления оценок: при каждом выборе веса суммируются по всем ключам объекта weights, после чего осуществляется переход к следующему сценарию или завершение теста.

**Расширенный тест** включает дополнительные форматы вопросов:

а) **Шкальные вопросы (scale)** — пользователь устанавливает значение на ползунке (range input). Обработчик считывает выбранное значение и нормализует его к диапазону весов.

б) **Открытые вопросы (open)** — текстовый ответ в свободной форме через textarea. Анализ текста выполняется по ключевым словам для определения тональности ответа.

в) **Ситуационные вопросы (situational)** — многошаговые сценарии, в которых каждый шаг предлагает новый выбор, а итоговая оценка складывается из всех шагов.

**Когнитивный тест** оценивает когнитивный стиль мышления через специализированные задания, включающие задачи на логику, ассоциативное мышление и анализ паттернов. Результаты когнитивного теста сохраняются отдельно и отображаются на странице профиля.

## 3.3 Реализация модуля анализа личности

Модуль анализа реализован в классе PersonalityAnalyzer и выполняет полный цикл обработки результатов тестирования.

**Метод нормализации:** реализует формулы (1)–(4) из раздела 2.2.2:

```javascript
normalizeScores(rawScores, scenarioCount) {
    const normalized = {};
    const dimensions = [
        'rationality', 'control', 'strategic',
        'explorer', 'individualism', 'meaning'
    ];

    dimensions.forEach(dim => {
        const sum = rawScores[dim] || 0;
        const avg = sum / scenarioCount;
        normalized[dim] = Math.max(-1, Math.min(1, avg));
    });

    return normalized;
}
```

**Генерация текстового профиля** включает:

а) определение доминирующих измерений (|Score| > 0.5);

б) формирование описания на основе шаблонов, учитывающих комбинацию измерений;

в) выделение сильных сторон на основе крайних значений;

г) генерация описания в формате, удобном для пользователя.

**Определение архетипа** основано на сравнении профиля пользователя с набором эталонных архетипов. Каждый архетип характеризуется: именем, описанием, набором пороговых условий по измерениям, цветом (для визуализации), иконкой и списком знаменитых представителей. Система выбирает архетип с максимальным процентом соответствия.

**Дополнительные модули анализа:**

а) `ComparativeAnalysis` — сравнение с эталонными профилями профессиональных ролей (предприниматель, исследователь, менеджер, творец, социальный работник и др.). Для каждой роли задан идеальный вектор значений по 6 измерениям, и рассчитывается евклидово расстояние между профилем пользователя и идеалом роли.

б) `CelebrityService` — определение известных личностей с похожим профилем предпочтений. База данных включает более 20 персон, сгруппированных по категориям (учёные, предприниматели, деятели искусства).

в) `EvolutionTracker` — анализ изменений профиля при повторных прохождениях. Модуль выявляет тренды (рост, снижение, стабильность) для каждого измерения и визуализирует динамику через линейные графики.

## 3.4 Реализация модуля визуализации

Модуль визуализации реализован в классе ResultsVisualizer и включает следующие типы диаграмм.

**Радарная диаграмма** — основная визуализация профиля по всем 6 измерениям. Реализация:

```javascript
createRadarChart(scores, dimensions) {
    const ctx = document.getElementById('radarChartContainer');
    const labels = Object.keys(dimensions).map(
        key => dimensions[key].name
    );
    const data = Object.keys(dimensions).map(key => {
        const val = scores[key] || 0;
        return Math.round((val + 1) * 50); // Формула (4)
    });

    this.radarChart = new Chart(ctx, {
        type: 'radar',
        data: {
            labels: labels,
            datasets: [{
                label: 'Профиль',
                data: data,
                backgroundColor: 'rgba(99, 102, 241, 0.2)',
                borderColor: 'rgba(99, 102, 241, 1)',
                pointBackgroundColor: 'rgba(99, 102, 241, 1)'
            }]
        },
        options: {
            responsive: true,
            scales: {
                r: { min: 0, max: 100 }
            }
        }
    });
}
```

**Столбчатая диаграмма** — альтернативное представление с точными процентными значениями.

**Сравнительная диаграмма** — наложение двух профилей (пользователь и эталонная роль) на одной радарной диаграмме с различными цветами.

**Диаграмма эволюции** — линейная диаграмма, отображающая изменение значений по измерениям между двумя сессиями тестирования.

Все диаграммы адаптивны — они автоматически масштабируются при изменении размера окна браузера. Реализована плавная анимация при построении диаграмм, что улучшает пользовательский опыт.

## 3.5 Реализация дополнительных модулей

**Модуль локализации (i18n.js).** Обеспечивает поддержку трёх языков: казахского (kk), русского (ru) и английского (en). Реализация основана на файлах JSON, содержащих пары «ключ — перевод». Пример:

```json
{
    "startTest": "Тестті бастау",
    "resultsTitle": "Нәтижелер",
    "rationalityName": "Ұтымдылық"
}
```

Элементы DOM с атрибутом data-i18n автоматически обновляются при смене языка через метод updateStaticContent(). Переключение языка сохраняется в localStorage и восстанавливается при следующем запуске.

**Модуль хранения (StorageManager).** Обеспечивает:

а) сохранение результатов тестирования с временной меткой и типом теста;
б) сохранение прогресса незавершённого теста (номер текущего сценария и накопленные веса);
в) хранение полной истории прохождений для построения эволюции;
г) управление настройками (язык, тема, параметры доступности).

Все данные сериализуются в JSON и хранятся под уникальными ключами в localStorage.

**Service Worker (sw.js).** Реализует стратегию «Cache First» для статических ресурсов: HTML, CSS, JS, шрифты и изображения кэшируются при первом запуске. При последующих запусках ресурсы загружаются из кэша, обеспечивая работу офлайн. При наличии сети проверяются обновления версии.

**Модуль генерации отчётов (ReportGenerator).** Создаёт автономный HTML-документ с результатами, который пользователь скачивает через метод download(). Отчёт включает: заголовок с логотипом, дату, имя пользователя, контент из ResultsView (архетип, оценки, рекомендации) и стили для печати.

**Модуль аутентификации (AuthManager).** Реализует опциональную аутентификацию через Google OAuth 2.0. При входе через Google результаты привязываются к аккаунту. Пользователь может продолжить как гость — в этом случае данные хранятся анонимно.
